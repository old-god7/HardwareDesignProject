# MIPS 五级流水线 CPU 设计文档

## 项目概述

本项目实现了一个完整的MIPS五级流水线CPU，支持MIPS-I指令集及部分MIPS-II/III扩展指令。设计采用Verilog硬件描述语言，实现了52+条指令，包括算术逻辑运算、分支跳转、内存访问、异常处理等完整功能。

### 主要特性

- ✅ **五级流水线架构**（IF-ID-EX-MEM-WB）
- ✅ **延迟槽机制**（Delay Slot）
- ✅ **完整的分支跳转指令**（8条B类 + 4条J类）
- ✅ **冒险检测与处理**（数据前推、停顿）
- ✅ **精确异常处理**（CP0协处理器）
- ✅ **HI/LO寄存器支持**（乘除法指令）
- ✅ **多种内存访问模式**（字/半字/字节，有符号/无符号）

## 关键设计决策

### 1. 延迟槽机制

**设计思想**：
- 分支/跳转指令后的一条指令（延迟槽）总是执行
- 编译器负责填充有用指令或NOP
- 减少控制冒险带来的性能损失

**实现要点**：
- 分支判断在ID阶段完成（提前）
- 正常跳转时不冲刷流水线
- 延迟槽指令正常流过流水线

**优势**：
- 有效分支延迟仅1个周期
- 无需分支预测和推测执行
- 流水线控制简单

### 2. 提前分支判断

**设计思想**：
- 将分支条件判断从EX阶段提前到ID阶段
- 在ID阶段完成寄存器读取、比较、目标地址计算

**实现要点**：
- 集成Branch_Cmp模块在ID阶段
- 从MEM阶段前推数据到ID阶段（解决数据冒险）
- 检测分支寄存器冲突，必要时停顿

**优势**：
- 减少分支延迟到1个周期（延迟槽）
- 提高流水线吞吐率

### 3. 完善的冒险处理

**数据前推**：
- **EX阶段前推**：从MEM/WB阶段前推到EX阶段（ALU操作数）
- **ID阶段前推**：从MEM阶段前推到ID阶段（分支/跳转操作数）

**停顿机制**：
- **Load-Use冒险**：Load指令后紧跟使用该数据的指令，停顿1周期
- **分支-ALU冒险**：分支前的ALU指令修改分支所需寄存器，停顿1周期
- **分支-Load冒险**：分支前的Load指令修改分支所需寄存器，停顿1周期

**冲刷逻辑**：
- 停顿时在EX阶段插入气泡（NOP）
- 异常时冲刷流水线（杀死年轻指令）

### 4. 精确异常

**设计思想**：
- 异常在MEM阶段提交（commit）
- 保证异常前的指令全部完成，异常后的指令全部不生效

**实现要点**：
- 异常信息通过流水线传递（exc_valid, exc_code）
- 检测到异常后，阻止新指令进入流水线（exc_hold）
- 异常提交时更新CP0寄存器，跳转到异常处理程序

**支持的异常**：
- Int（中断）
- AdEL（取指/Load地址错误）
- AdES（Store地址错误）
- Sys（系统调用）
- Bp（断点）
- RI（保留指令）
- Ov（溢出）

## 性能特性

### CPI（每指令周期数）

理想情况下（无冒险、无分支）：
- **CPI = 1**（每周期执行1条指令）

实际情况（考虑冒险）：
- **Load-Use冒险**：额外1个周期
- **分支冒险**：额外0-1个周期（取决于前面指令）
- **除法指令**：额外32个周期（除法器忙）

### 流水线效率

- **5级流水线**：理论加速比接近5倍
- **延迟槽**：减少分支惩罚，提高吞吐率
- **前推机制**：避免大部分数据冒险的停顿

## 答辩要点

### 关于B/J类指令

**Q: 这些指令在哪里定义？**
- A: 在`maindec2.v`中根据opcode和rt字段译码，生成控制信号；JR/JALR在`controller2.v`中特殊检测。

**Q: 如何判断分支是否跳转？**
- A: 在ID阶段，`Branch_Cmp.v`模块根据branch_op类型比较两个寄存器值，输出equalD信号；`pcsrcD = branchD & equalD`决定是否跳转。

**Q: 为什么要提前分支判断？**
- A: 传统设计在EX阶段判断，分支延迟为2-3个周期。提前到ID阶段判断，配合延迟槽，有效分支延迟降为1个周期。

**Q: 延迟槽指令何时执行？**
- A: 在分支/跳转指令后立即取出，在分支判断的同时进入流水线，总是执行，无论分支是否跳转。

**Q: 如何处理分支的数据冒险？**
- A: 通过前推和停顿。如果MEM阶段有可用数据，前推到ID阶段；如果数据还在EX阶段或是Load指令，则停顿1个周期。

### 关于五级流水线

**Q: 五个阶段分别做什么？**
- A: IF取指令、ID译码和读寄存器（含分支判断）、EX执行ALU运算、MEM访问内存（含异常提交）、WB写回寄存器。

**Q: 每个阶段由哪些模块实现？**
- A: 详见[五级流水线详解](./文档_五级流水线详解.md)，每个阶段都有详细的模块、文件、代码行数说明。

**Q: 如何处理数据冒险？**
- A: 通过前推和停顿。`hazard.v`检测冒险，生成forwardaE/forwardbE控制前推，生成stallD控制停顿。

**Q: 流水线寄存器在哪里？**
- A: IF/ID(r1D, r2D), ID/EX(r1E-r11E), EX/MEM(r1M-r4M), MEM/WB(r1W-r4W)，都在`datapath.v`中。

**Q: 异常如何处理？**
- A: 异常在Decode阶段检测，随指令流过流水线，在MEM阶段提交。提交时更新CP0寄存器，跳转到异常处理入口（0xBFC00380）。
